ADF VS SQL agent

If you've already migrated SQL Agent jobs to ADF and want to compare SQL Agent jobs against ADF pipelines, a simple reconciliation approach is:

Step 1: Extract Disabled SQL Agent Jobs
SELECT
    name AS SqlAgentJob
FROM msdb.dbo.sysjobs
WHERE enabled = 0
ORDER BY name;

Export this to Excel as SQLAgentJobs.xlsx.

Step 2: Extract ADF Pipelines

There are several ways:

Option A: From Azure Portal
Open ADF Studio
Author → Pipelines
Export list manually
Option B: Using PowerShell
Get-AzDataFactoryV2Pipeline `
    -ResourceGroupName "RGName" `
    -DataFactoryName "ADFName" |
Select-Object Name |
Export-Csv ADFPipelines.csv -NoTypeInformation
Step 3: Match in Excel

Assume:

Sheet1 (SQL Jobs)

A
JobName

Sheet2 (ADF Pipelines)

A
PipelineName

Use:

=XLOOKUP(A2,ADF!A:A,ADF!A:A,"Not Found")

or

=IF(COUNTIF(ADF!A:A,A2)>0,"Migrated","Missing")

Result:

SQL Job	Status
Customer_Load	Migrated
Invoice_Export	Missing
Step 4: Better Approach (Recommended)

Create a migration inventory table:

SQL Agent Job	Status	ADF Pipeline	Trigger	Remarks
Job_A	Disabled	PL_Job_A	Daily	Migrated
Job_B	Disabled	PL_Job_B	Hourly	Migrated
Job_C	Disabled	NULL	NULL	Not Migrated

Then use SQL:

SELECT
    j.name AS SqlAgentJob,
    CASE
        WHEN m.AdfPipeline IS NULL THEN 'Not Migrated'
        ELSE 'Migrated'
    END AS MigrationStatus,
    m.AdfPipeline
FROM msdb.dbo.sysjobs j
LEFT JOIN MigrationMapping m
    ON j.name = m.SqlAgentJob
WHERE j.enabled = 0;

This is usually the cleanest approach for migration audits because job names and pipeline names often differ (e.g., WTC_Customer_Load vs PL_Customer_Load).

Run:

$Results = @()

Get-ChildItem -Recurse *.json | ForEach-Object {

    $json = Get-Content $_.FullName -Raw

    if($json -match "AzureFunction")

        $Results += [PSCustomObject]@{

Query 1 – Disabled SQL Agent Jobs
USE msdb;
GO

SELECT
    j.name AS JobName,
    CASE
        WHEN j.enabled = 1 THEN 'Enabled'
        ELSE 'Disabled'
    END AS JobStatus,
    SUSER_SNAME(j.owner_sid) AS JobOwner,
    j.date_created,
    j.date_modified
FROM dbo.sysjobs j
WHERE j.enabled = 0
ORDER BY j.name;

USE msdb;

SELECT
    j.name AS JobName,
    j.enabled AS JobEnabled,
    s.name AS ScheduleName,
    s.enabled AS ScheduleEnabled
FROM dbo.sysjobs j
LEFT JOIN dbo.sysjobschedules js
    ON j.job_id = js.job_id
LEFT JOIN dbo.sysschedules s
    ON js.schedule_id = s.schedule_id
WHERE j.enabled = 0
ORDER BY j.name;


Query 3 – Complete Migration Inventory
SELECT
    j.name AS JobName,
    CASE
        WHEN j.enabled = 1 THEN 'Enabled'
        ELSE 'Disabled'
    END AS JobStatus,
    c.name AS Category,
    SUSER_SNAME(j.owner_sid) AS Owner,
    j.date_created,
    j.date_modified
FROM msdb.dbo.sysjobs j
LEFT JOIN msdb.dbo.syscategories c
    ON j.category_id = c.category_id
ORDER BY j.enabled,
         j.name;

Additional Useful Query – Jobs Used by ADF Migration Assessment

USE msdb;
GO

SELECT
    j.name AS JobName,
    CASE WHEN j.enabled = 1 THEN 'Enabled'
         ELSE 'Disabled'
    END AS Status,
    c.name AS Category,
    COUNT(js.step_id) AS StepCount,
    MAX(h.run_date) AS LastRunDate
FROM dbo.sysjobs j
LEFT JOIN dbo.syscategories c
    ON j.category_id = c.category_id
LEFT JOIN dbo.sysjobsteps js
    ON j.job_id = js.job_id
LEFT JOIN dbo.sysjobhistory h
    ON j.job_id = h.job_id
    AND h.step_id = 0
GROUP BY
    j.name,
    j.enabled,
    c.name
ORDER BY j.name;
