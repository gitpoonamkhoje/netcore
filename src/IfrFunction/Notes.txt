APT: as-is conversion (AptApplyTransformations=false)
SPECTR: logo + **bold** + __underline__ (SpectrApplyTransformations=true)

How it works
1. APT vs SPECTR comes from the blob path:

Upload path				Source
ifr/apt/inbound/file.txt		APT
ifr/spectr/inbound/file.txt		SPECTR

2. Transformations come from AppResources settings:

Setting				Default		Used when
AptApplyTransformations		false		File is under apt/...
SpectrApplyTransformations	true		File is under spectr/...

In AptSpectrBlobProcessor, that logic is:

        var applyTransformations = source == AptSpectrSources.Apt
            ? _resources.AptApplyTransformations
            : _resources.SpectrApplyTransformations;
So:

APT file in blob → applyTransformations = false (as-is PDF)
SPECTR file in blob → applyTransformations = true (logo, bold, underline)

Config (not per-file input)
In local.settings.json or app settings:

"AppResources__AptApplyTransformations": "false",
"AppResources__SpectrApplyTransformations": "true"

1) **EBR Process Overview**

The process strips the line and creates an index in SQL to determine when each job should start and when each statement processing should end.

In the production (PROD) environment, the job starts every Tuesday at **7:00 AM**.

For the EBR process, the input will be provided by **GMC**. GMC will generate an input file, which may contain approximately **200 records**, to be converted into PDF files as part of the new processing flow.

The client has confirmed that the input files will be delivered to **Blob Storage**.

The initial EBR process is the same as the existing process. After the input files are received from GMC, they will be processed according to the new PDF generation flow.
