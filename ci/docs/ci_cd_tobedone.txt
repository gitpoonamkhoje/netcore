1) The existing migration template explicitly uses these for Azure login:
ARM_TENANT_ID
ARM_CLIENT_ID
ARM_CLIENT_SECRET
ARM_SUBSCRIPTION_ID

Ask your DevOps/Azure team:

"Please provide the existing GitLab CI/CD Azure service-principal credentials/variables for deploying the ODS Function App to DEV: ARM_TENANT_ID, ARM_CLIENT_ID, ARM_CLIENT_SECRET, and ARM_SUBSCRIPTION_ID."

They should ideally already have these configured as GitLab CI/CD protected/masked variables at the group/project level.

| Variable              | Where it comes from                                       | What it represents                              |
| --------------------- | --------------------------------------------------------- | ----------------------------------------------- |
| `ARM_TENANT_ID`       | Azure Entra ID → **Tenant ID**                            | Your organization's Azure tenant                |
| `ARM_CLIENT_ID`       | Entra ID → **App registration → Application (client) ID** | Service principal/application used by CI/CD     |
| `ARM_CLIENT_SECRET`   | Entra ID → **App registration → Certificates & secrets**  | Secret for that service principal               |
| `ARM_SUBSCRIPTION_ID` | Azure Portal → **Subscriptions → Subscription ID**        | Azure subscription containing your Function App |
